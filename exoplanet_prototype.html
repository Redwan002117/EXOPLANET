Exoplanet Transit Detection System

A machine-learning pipeline for classifying Kepler and TESS light curves as exoplanet candidates or false positives. Built for IUBAT CSC 488 Thesis — combining traditional ML interpretability with deep-learning accuracy.

The system trains nine ML models (XGBoost, Random Forest, LightGBM, and more) plus a dual-view 1D convolutional neural network on phase-folded photometric light curves from NASA's MAST archive. Every prediction is explained via SHAP (for the ensemble) and Grad-CAM (for the CNN).

Data Collection

Light curves are downloaded from NASA MAST via the lightkurve library. For each KOI, the pipeline:

  1. Resolves the KIC (Kepler Input Catalog) number from the NASA Exoplanet Archive.
  2. Downloads all available quarters of long-cadence Kepler photometry (~29.4 min cadence).
  3. Stitches quarters together, normalises, removes NaN values, and sigma-clips outliers (5σ).
  4. Fetches the orbital period and archive disposition (CONFIRMED / FALSE POSITIVE) from the Cumulative KOI table via TAP.
  5. Phase-folds the light curve onto the orbital period and bins into 2000 equidistant phase bins.

TESS targets follow the same process using the TOI table and lightkurve.search_lightcurve(…, mission='TESS').

Preprocessing

Each phase-folded light curve passes through a four-step preprocessing chain:

  1. NaN interpolation — linear interpolation fills any missing cadences.
  2. Savitzky–Golay detrending — a window-51, poly-3 SG filter estimates the stellar variability trend; dividing by this trend removes long-term systematics while preserving the transit shape.
  3. Median normalisation — flux is divided by its median so the out-of-transit baseline sits at 1.0.
  4. Resampling to 2000 points — all curves are interpolated to a fixed length, enabling batch training.

A local view (200 points centred on phase 0.5, representing the transit) is also extracted for the DualViewCNN. This zoomed view captures ingress/egress detail that the global view blurs at 2000-point resolution.

Phase convention: The transit is placed at phase 0.5. The highlighted green band in all light curve plots marks the expected transit window (phase 0.45–0.55).

Feature Extraction (30 Features)

For the traditional ML models, 30 scalar features are extracted from each preprocessed global light curve. These capture physical transit diagnostics used by human astronomers:

Transit Shape Features

  • transit_depth — difference between median flux and the minimum (proxy for Rp/R☉).
  • transit_duration — fraction of phase in transit (below 50% depth threshold).
  • flat_fraction — fraction of in-transit points near the bottom (flat-bottom = planet, V-shape = eclipsing binary).
  • transit_symmetry — mean absolute flux difference between ingress and egress halves.
  • vshape_index — ratio of mean-to-min inside transit; low = flat-bottom (planet).
  • ingress_proxy — mean slope at transit edges; steep = V-shape = binary.
  • bottom_flatness — std of deepest 50% of in-transit points; low = true planet.
  • ld_proxy — quadratic coefficient of polynomial fit inside transit (limb darkening proxy).

Signal Quality Features

  • snr — transit depth / out-of-transit noise std.
  • snr_robust — depth / (1.4826 × MAD), more robust to outliers than SNR.
  • depth_snr — depth / overall flux std.
  • scatter_ratio — in-transit scatter / out-of-transit scatter.
  • oot_range — 99th–1st percentile of out-of-transit flux (stellar variability).
  • outlier_fraction — fraction of OOT points more than 3σ from median.

False-Positive Diagnostics

  • even_odd_diff — depth difference between first/second half of the LC (eclipsing binaries show alternating depths).
  • secondary_depth / secondary_ratio — depth at phase 0.5±0.05 (secondary eclipse).
  • sec03_ratio, sec07_ratio — secondary eclipses at eccentric phases 0.27–0.33 and 0.67–0.73.
  • half_period_depth — eclipse at phase 0.0/1.0 (equal-depth EB indicator).
  • transit_phase_shift — |phase of flux minimum − 0.5|; small = well-aligned transit.

Statistical Features

  • centroid_skew — skewness of the flux distribution (proxy for photometric asymmetry; a high value indicates an asymmetric brightness profile, which can distinguish planetary transits from eclipsing binaries; note: this is a flux-distribution metric, not a photocenter position measurement).
  • kurtosis — excess kurtosis (sharp transit spike → high kurtosis).
  • std, mean, p5_p95_range — global flux statistics.
  • fold_quality — variance of the phase-folded curve (noisy fold = higher variance).
  • transit_count, transit_fill — number and fraction of in-transit points.

Stacking Ensemble

A StackingClassifier (scikit-learn) combines RF, ET, XGBoost, SVM, LR, and LightGBM as level-1 learners. Their out-of-fold probability predictions become input features for a logistic regression meta-learner. This is strictly more powerful than soft-voting because the meta-learner learns how much to trust each base model.

Class Imbalance

SMOTE oversamples the minority class in feature space before training. Tree models use class_weight='balanced_subsample'. XGBoost uses scale_pos_weight = n_negative / n_positive.

Hyperparameter Tuning

XGBoost and LightGBM are tuned with Optuna Bayesian optimisation (25 trials, TPE sampler, 3-fold stratified CV). Random Forest and Extra Trees use RandomizedSearchCV (15 iterations).

Decision Threshold

Each model uses Youden's J statistic to find an optimal threshold: threshold = argmax(TPR − FPR), capped at 0.5 to prioritise recall (missing a real planet is worse than a false alarm in exoplanet surveys).

DualView 1D Convolutional Neural Network

The CNN architecture is inspired by AstroNet (Shallue & Vanderburg, 2018) with several enhancements:

Architecture

  • Global branch — processes the full 2000-point phase-folded LC. Captures periodic context and long-range flux patterns.
  • Local branch — processes a 200-point zoomed view centred on the transit (phase 0.43–0.57). Captures fine-grained ingress/egress shape.
  • Each branch is a ViewEncoder: 2 strided conv blocks (Conv1d → BN → GELU → MaxPool) + 2 residual blocks + final 64→128-channel conv + adaptive global average pooling → 128-dim (global) or 64-dim (local) embedding.
  • Embeddings are concatenated (192-dim) and passed through a channel attention gate (squeeze-and-excitation style) that learns which embedding dimensions matter most.
  • Classification head: 192 → 64 → 2 (planet / non-planet) with GELU activations and 0.4 dropout.

Training Details

  • Loss: Focal Loss (γ=2, label smoothing=0.1) with class weights — handles imbalanced datasets by down-weighting easy examples.
  • Optimiser: AdamW (lr=5×10⁻⁴, weight_decay=3×10⁻⁴).
  • Scheduler: Cosine Annealing with Warm Restarts (T₀=20 epochs).
  • Augmentation: Gaussian noise (σ=0.003) + circular phase shift ±4% + Mixup (α=0.15, 50% of batches).
  • Early stopping: Patience=18 epochs on validation F1.
  • TTA: 7 augmented inference passes are averaged at prediction time.
Adaptive capacity: For small training sets (<30 samples), the network automatically reduces its embedding dimensions (128→64 global, 64→32 local) to prevent overfitting.

Explainability: SHAP + Grad-CAM

SHAP (XGBoost)

SHapley Additive exPlanations (Lundberg & Lee, 2017) compute each feature's contribution to a single prediction by averaging over all possible feature orderings. For XGBoost, TreeExplainer computes exact SHAP values in polynomial time.

The prototype shows the top-8 SHAP features per star, sorted by |SHAP value|. Blue bars = feature pushed the prediction toward planet; red bars = toward non-planet.

Grad-CAM (DualView CNN)

Gradient-weighted Class Activation Mapping (Selvaraju et al., 2017) identifies which time-steps in the global light curve most influenced the CNN's decision. Gradients flow back from the target class logit to the last convolutional layer (64→128 channels); the gradient-weighted sum of feature maps produces a 1D activation map.

The red overlay on the light curve canvas shows this activation — high activation inside the transit window (phase 0.45–0.55) confirms the CNN is reasoning about the transit dip rather than noise elsewhere.

Explainability Metrics

  • SHAP Faithfulness — accuracy drop when the top-3 SHAP features are masked with their median values. Positive = the explanation correctly identifies the most important features.
  • SHAP Sparsity — fraction of |SHAP| values < 0.01. Higher = the model uses fewer, more distinct features to decide.
  • SHAP Consistency — mean Spearman rank correlation of feature importance across all stars. Near 1.0 = the model uses the same reasoning for every prediction.
  • Grad-CAM Localization — fraction of total CNN activation inside the transit window. 1.0 = perfectly focused on the transit; <0.3 may indicate the CNN is distracted by noise or stellar variability.

Metric Definitions

MetricRangeDefinition
Accuracy0 – 1 Fraction of all predictions that are correct: (TP+TN)/(TP+FP+FN+TN).
Precision0 – 1 Of all stars predicted "planet", what fraction are truly planets? TP/(TP+FP). High precision = fewer false alarms.
Recall (Sensitivity)0 – 1 Of all true planets, what fraction did the model find? TP/(TP+FN). High recall = fewer missed planets. Prioritised in exoplanet search.
F1 Score0 – 1 Harmonic mean of Precision and Recall: 2·P·R/(P+R). Balances both goals; used as the primary optimisation target.
AUC-ROC0.5 – 1 Area Under the ROC Curve. Probability that the model ranks a random planet higher than a random non-planet. 0.5 = random; 1.0 = perfect.
MCC−1 – 1 Matthews Correlation Coefficient. Considers all four confusion matrix cells; most informative for imbalanced datasets. 0 = random; 1 = perfect.
CV F1 ± σ0 – 1 Mean F1 across 5-fold stratified cross-validation ± standard deviation. More reliable than a single train/test split for small datasets.
CNN Confidence0 – 1 Softmax probability for the "planet" class, averaged over 7 Test-Time Augmentation passes. >0.5 = predicted planet (threshold may be lower due to Youden's J optimisation).

Data Sources

  • Kepler Mission (NASA) — 4-year photometric survey of ~150,000 stars. Long-cadence (~29.4 min) light curves downloaded via MAST. Labels from the Cumulative KOI Table on the NASA Exoplanet Archive.
  • TESS Mission (NASA) — all-sky survey; 2-min and 30-min cadence. Labels from the TESS Object of Interest (TOI) table.
  • lightkurve — open-source Python library for Kepler/TESS data.
  • NASA Exoplanet Archive TAP — Table Access Protocol endpoint used to fetch orbital periods, transit parameters, and archive dispositions at runtime.

Frequently Asked Questions

Why are Accuracy and F1 the same for every star?

These are model-level metrics computed once on the test set, not per-star metrics. They describe how well the model performs overall. The per-star information is the confidence score and prediction in the "This Star" column.

Why does the light curve look noisy or flat for some stars?

Some false positives or very shallow transits (e.g., sub-Mercury planets) have extremely small transit depths (<100 ppm), which may appear as a nearly flat line after normalisation. The Grad-CAM activation pattern is more informative than the raw flux in these cases.

What does a Grad-CAM localization score near 0 mean?

It means the CNN focused its attention outside the transit window — possibly on stellar variability, instrumental artefacts, or secondary eclipses. This can indicate a false positive or a poorly phase-folded light curve.

Can I add my own CSV light curve?

Yes — the pipeline's load_csv() function accepts any CSV with time and flux columns. Run it through Colab via --mode csv in pipeline.py, or modify Cell 4 to load your file from Google Drive.

Why does the model sometimes disagree with NASA?

The model is trained on a subset of KOIs and may not generalise perfectly to all cases. A mismatch can also indicate a genuinely ambiguous light curve — cases where even expert astronomers disagree. Always treat ML predictions as a screening tool, not a final verdict.

What is the "Stacking Ensemble"?

A meta-learning approach where the predictions of multiple base models (RF, ET, XGBoost, SVM, LR, LightGBM) are used as input features for a second-level logistic regression classifier. This learns the optimal combination of base model outputs, typically outperforming any individual model.
